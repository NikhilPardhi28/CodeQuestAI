# Unity client foundation

## Editor and packages

Open this project with Unity **6000.3.19f1**. `ProjectSettings/ProjectVersion.txt` pins that installed editor build. `Packages/manifest.json` pins URP 17.3.0, Unity Test Framework 1.6.0, and uGUI 2.0.0, all verified in the editor's bundled package directory. The legacy Input Manager is used behind `IGameInput`; the Input System package is not installed or assumed. Open the project once in Unity Hub/Editor to resolve packages and generate `Packages/packages-lock.json`; current source `.meta` files are already checked in. Do not upgrade the editor or packages automatically.

### First open and scene setup

1. In Unity Hub, choose **Add** and select `D:\CodeQuestAI\GameClient`.
2. Open it with **6000.3.19f1** and wait for package resolution and script compilation.
3. From the editor menu choose **CodeQuest → Setup URP and Bootstrap Scene**. This creates the URP renderer/pipeline assets, the non-secret API settings asset, and `Assets/Scenes/Bootstrap.unity`, and adds that scene to Build Settings.
4. Open `Assets/Scenes/Bootstrap.unity` and press Play. The bootstrap composes a temporary primitive ground/player/camera and runtime UI if no authored player scene objects exist. The greybox is disposable scaffolding, not game content.
5. In **Edit → Project Settings → Player → Other Settings → Configuration**, set **Active Input Handling** to **Input Manager (Old)**. The inspected project does not include the new Input System package; Unity documents the old manager and Both modes as supported input handling choices ([Unity input handling](https://docs.unity3d.com/6000.0/Manual/UIE-Runtime-Event-System.html)).

Project setup uses a Unity editor menu command because project assets, render pipeline settings, scene serialization, and package lockfiles must be generated by this exact editor. The editor executable was found at `C:\Program Files\Unity\Hub\Editor\6000.3.19f1\Editor\Unity.exe`. Batch import stopped with Unity exit code 198 because no valid editor license was active. Open Unity Hub and sign in; for Personal, if Hub has not activated a license, choose **Settings → Licenses → Add license → Get a free personal license → Agree and get personal edition license** ([Unity license steps](https://docs.unity.com/hub/manage-license)). Then follow the project-open steps above. Package resolution/lock generation, URP activation, Unity compilation, and Test Runner execution are still pending.

## Runtime modules

- `CodeQuest.Core`: game-state and scene-transition interfaces, player-state contract.
- `CodeQuest.Gameplay`: input abstraction, third-person motor, camera rig, and interaction contracts.
- `CodeQuest.Networking`: typed DTOs, cancellable UnityWebRequest API client, and token-provider boundary.
- `CodeQuest.UI`: bootstrap composition root and functional runtime menu/catalog/profile UI.
- `CodeQuest.Editor`: editor-only setup action; no UnityEditor dependency enters runtime assemblies.

No external dependency-injection framework is used. `CodeQuestBootstrap` composes the initial services. Runtime UI provides connection/readiness feedback, recoverable API errors, catalog retrieval, and a profile panel that stays unauthenticated until a real token provider is configured.

## Controls

- **WASD**: walk; **Left/Right Shift**: run; **Space**: jump.
- **Mouse**: camera look; **E**: interact with the nearest nearby `IInteractable`.
- **Escape**: open/close the menu. Click **Start exploring** to lock the cursor for camera look.

The current adapter uses the legacy Unity Input Manager axes (`Horizontal`, `Vertical`, `Jump`, and mouse axes). Replace it behind `IGameInput` when controller rebinding is introduced.

## API configuration and startup

The editor setup command creates `Assets/Resources/ApiClientSettings.asset` with the local default `http://127.0.0.1:8000`; edit its Base URL for the environment. This works when the Unity Editor and backend share the same Windows host. A deployed client must use its reachable HTTPS service URL; do not assume `localhost` identifies the server from another machine. This asset contains no credential. The API client never sends profile requests without an `IAccessTokenProvider` token; the current composition uses an honest unauthenticated provider because the OIDC provider remains unselected.

From repository root, start the backend and PostgreSQL as described in [backend setup](../BackendAPI/README.md) and [database setup](../Database/README.md):

```powershell
docker compose -f Infrastructure/compose.yaml up -d postgres
uv run python -m alembic upgrade head
uv run python -m BackendAPI.app.db.seed
uv run python -m uvicorn BackendAPI.app.main:app --reload
```

The Unity client calls `/healthz`, `/readyz`, `/api/v1/curriculum/regions`, `/api/v1/curriculum/objectives`, `/api/v1/quests`, `/api/v1/challenges`, and authenticated `/api/v1/me`. Response DTOs follow the checked-in [OpenAPI contract](../Documentation/api/openapi-v1.json); no sample/fake response is substituted when the API is unavailable. The profile call currently returns a local unauthenticated state.

## Tests

After opening the project and allowing compilation, use **Window → General → Test Runner**. Run EditMode and PlayMode suites. EditMode covers movement rules and backend JSON DTO parsing; PlayMode covers movement, interface-based interaction, and bootstrap composition. These suites have not yet been run in this environment because Unity batch mode did not create/import the project. Python contract tests remain runnable from repository root with `uv run python -m pytest`.

## Limits and next milestone

The current Unity client is a greybox runtime foundation. It does not include authored world scenes/assets, controller remapping, a configured OIDC identity provider, profile sign-in, profile writes, persistence, quest mutation, dialogue, challenge authoring/execution, multiplayer, or production error telemetry. Scene transitions are available through the build-settings-backed service interface but no additional scenes exist yet. The Unity editor must generate the initial scene/settings and lockfile before compilation or PlayMode status can be claimed.

Next milestone: reusable world interaction and authored interactables, followed by quest state, dialogue, player persistence, and the learning challenge framework against the existing backend contracts.
