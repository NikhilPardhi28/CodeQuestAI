# PostgreSQL CI schema initialization

The `postgres-integration` Actions job sets `CODEQUEST_TEST_DATABASE_URL` to its PostgreSQL 17.5 service database, `codequest_test`. The migration integration test and both concurrency tests read that same variable. Each test checks the isolated database, runs Alembic `upgrade head`, and calls `seed_development` before issuing catalog or progression queries. The authoritative migration command is `uv run python -m alembic upgrade head`, also used by the tests through Alembic's Python API with an explicit `Database/migrations` script location and that URL.

The repository-level failure mechanism was that the “empty database” checks treated any `alembic_version` table as harmless, without checking or resetting its revision stamp. If that stamp says `head` while application tables are absent, Alembic can no-op and the subsequent seed query can raise `UndefinedTable`. The reported error is consistent with this state; the available log excerpt does not show the version-table contents, so the exact state in that Actions run still needs confirmation. The shared test helper now permits only an empty database (no application tables), drops the leftover Alembic version table if present, and lets each test apply the migrations afresh. It never drops application tables, and the tests still fail if those tables already exist. Seed data continues to be inserted only after upgrade.

The SQLite HTTP fixture is different: it creates ORM metadata directly with `Base.metadata.create_all`, then calls `seed_development`. The SQLite migration round-trip uses Alembic against a temporary file database. Neither path establishes PostgreSQL concurrency behavior.

Local validation after this change: focused migration/concurrency test invocation reported **1 passed, 3 skipped** because `CODEQUEST_TEST_DATABASE_URL` is not configured; full-suite result and static checks are in the task report. The PostgreSQL CI job has not yet been rerun, so this change is not reported as verified against PostgreSQL. Rerun `postgres-integration` and require that job to pass before considering the incident resolved.
