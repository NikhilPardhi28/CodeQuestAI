# Unity client foundation

## Editor and packages

Open this project with Unity **6000.3.19f1**. `ProjectSettings/ProjectVersion.txt` pins that installed editor build. `Packages/manifest.json` pins URP 17.3.0, Unity Test Framework 1.6.0, and uGUI 2.0.0, all verified in the editor's bundled package directory. The legacy Input Manager is used behind `IGameInput`; the Input System package is not installed or assumed. Open the project once in Unity Hub/Editor to resolve packages and generate `Packages/packages-lock.json`; current source `.meta` files are already checked in. Do not upgrade the editor or packages automatically.

### First open and scene setup

1. In Unity Hub, choose **Add** and select `D:\CodeQuestAI\GameClient`.
2. Open it with **6000.3.19f1** and wait for package resolution and script compilation.
3. From the editor menu choose **CodeQuest → Setup URP and Bootstrap Scene**. This creates the URP renderer/pipeline assets, the non-secret API settings asset, and `Assets/Scenes/Bootstrap.unity`, and adds that scene to Build Settings.
4. Open `Assets/Scenes/Bootstrap.unity` and press Play. The bootstrap composes the third-person player/camera, runtime UI, Signal Keeper foundation, Mira's mentor dialogue, and a primitive Variable Valley path, gate, and beacon. These primitives are a playable greybox built from Unity primitives and can later be replaced by authored licensed assets.
5. In **Edit → Project Settings → Player → Other Settings → Configuration**, set **Active Input Handling** to **Input Manager (Old)**. The inspected project does not include the new Input System package; Unity documents the old manager and Both modes as supported input handling choices ([Unity input handling](https://docs.unity3d.com/6000.0/Manual/UIE-Runtime-Event-System.html)).

Project setup uses a Unity editor menu command because project assets, render pipeline settings, scene serialization, and package lockfiles must be generated by this exact editor. The executable used for verification is `C:\Program Files\Unity\Hub\Editor\6000.3.19f1\Editor\Unity.exe`. Compilation and EditMode/PlayMode runs completed for Milestone 9; see [the verification report](../Documentation/milestone-9-vertical-slice.md).

## Runtime modules

- `CodeQuest.Core`: game-state and scene-transition interfaces, player-state contract.
- `CodeQuest.Gameplay`: input abstraction, third-person motor, camera rig, and interaction contracts.
- `CodeQuest.Networking`: typed DTOs, cancellable UnityWebRequest API client, and token-provider boundary.
- `CodeQuest.UI`: bootstrap composition root and functional runtime menu/catalog/profile UI.
- `CodeQuest.Editor`: editor-only setup action; no UnityEditor dependency enters runtime assemblies.

No external dependency-injection framework is used. `CodeQuestBootstrap` composes the initial services. On Windows Editor/standalone builds it uses the local Keycloak Authorization Code + PKCE provider; other platforms retain the fail-closed unauthenticated provider. Runtime UI provides connection/readiness feedback, catalog retrieval, profile access, and quest refresh after sign-in. The real Keycloak flow has not yet been verified end to end in this environment.

## Controls

- **WASD**: walk; **Left/Right Shift**: run; **Space**: jump.
- **Mouse**: camera look; **E**: interact with the nearest nearby `IInteractable`.
- **Escape**: open/close the menu. Click **Start exploring** to lock the cursor for camera look.

The current adapter uses the legacy Unity Input Manager axes (`Horizontal`, `Vertical`, `Jump`, and mouse axes). Replace it behind `IGameInput` when controller rebinding is introduced.

## API configuration and startup

The editor setup command creates `Assets/Resources/ApiClientSettings.asset` with the local default `http://127.0.0.1:8000`; edit its Base URL for the environment. This works when the Unity Editor and backend share the same Windows host. A deployed client must use its reachable HTTPS service URL; do not assume `localhost` identifies the server from another machine. This asset contains no credential. The API client never sends protected requests without an access token. Windows Editor/standalone uses the public `codequest-unity` client with Authorization Code + PKCE; see [local Keycloak setup](../Documentation/local-keycloak.md) for the exact redirect and audience mapper. No client secret is embedded in Unity.

From repository root, start the backend and PostgreSQL as described in [backend setup](../BackendAPI/README.md) and [database setup](../Database/README.md):

```powershell
docker compose -f Infrastructure/compose.yaml up -d postgres
uv run python -m alembic upgrade head
uv run python -m BackendAPI.app.db.seed
uv run python -m uvicorn BackendAPI.app.main:app --reload
```

The Unity client calls the public `/healthz`, `/readyz`, and v1 catalog routes plus v2 authenticated quest/progression reads and quest event writes. Response shapes follow [OpenAPI v1](../Documentation/api/openapi-v1.json) and [OpenAPI v2](../Documentation/api/openapi-v2.json); no fake response or credential is substituted when the API is unavailable. Protected calls fail closed if sign-in or token refresh is unavailable. The Windows Keycloak setup and live authenticated integration remain unverified until a real token successfully calls the backend.

## Limits and next milestone

The Variable Valley coding panel uses the published function contract, a multiline monospace editor, a local function-header-only check, catalog-provided deterministic hints, authenticated server submission/status polling, and sanitized visible-case feedback. It has no syntax highlighter and never executes code locally. Quest progress is authoritative and server-restored; interaction events remain pending/failed until confirmed. Its retry queue is bounded to 32 in-memory events and is lost on restart; queued events are never labeled cloud-saved. Windows OIDC and the live worker/evaluator are not operationally verified here, so real authenticated pass/progression integration remains unavailable.

Next milestone: finish licensed Unity verification and run the single challenge through real Keycloak authentication, evaluator submission, quest completion, and restored progress. Preserve the current fail-closed behavior until those services pass the security gates.
